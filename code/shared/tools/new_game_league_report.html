이전 리그와는 게임 버전과 주 판정 기준이 다릅니다. 순위 변화를 추가 학습 효과로 해석하면 안 됩니다.

01. 전체 순위

행의 모델 이름을 누르면 상대별 결과로 이동합니다. 승률과 순위용 승점률을 구분했습니다.

순위참가자완료 / 예정승 / 무 / 패승률평균 승점률 ↓Blue 승점률Red 승점률미완료

승률 = 승 ÷ 완료 경기. 순위용 평균 승점률 = 각 상대에 대한 (승 + 0.5 × 무) ÷ 완료 경기를 계산한 뒤 상대별 동일 비중 평균. 진영별 승점률은 해당 진영의 경기 기준입니다. 경기 수 차이 때문에 세 값이 다를 수 있습니다. 수치상 같은 승점률은 부동소수점 오차를 제외하고 공동 순위로 표시합니다.

02. 누구에게 이기고, 누구에게 졌나

기본 선택은 v12입니다. 다른 모델도 같은 방식으로 살펴볼 수 있습니다.

행 모델이 열 상대에게 얻은 승점률입니다. 셀을 누르면 대진 상세를 볼 수 있습니다.

모델·상대·결과를 선택하세요. 원본 링크는 각 경기의 저장된 판정과 실행 기록입니다.

반복BlueRed종료 팀 점수 B : R승자보상 기준 승자step원본

점수는 API가 기록한 정규화 값입니다. 원점수나 백분율로 환산하지 않았습니다. 누적 보상 기준 승자는 진단용이며 순위에 사용하지 않습니다. 전체 2,294경기를 이 파일에 포함했습니다.

05. 미완료 16경기

미완료는 패배나 무승부가 아닙니다. 모두 defender가 포함된 8개 대진에서 2경기씩 빠졌습니다.

대진미완료완료 / 예정마지막 기록
16경기 개별 기록과 오류 파일

저장된 마지막 상태는 모두 worker exit 1, 시도 번호 2입니다. 특정 상대에 집중된 사실만으로 정책 자체의 오류라고 단정할 수 없습니다. 상세 원인은 이 보고서에서 확정하지 않았습니다.

06. 읽는 방법과 실험 조건

평가 조건과 참가 모델

22개 참가자 · 231개 대진 · 대진마다 5개 환경 seed × 진영 교대 2경기. 최대 16개 병렬로 관전 창 1개는 1배속, 백그라운드 15개는 50배속을 요청했습니다. CPU 추론은 worker당 1스레드이며 GPU는 Unity 의미 지도 렌더링에 사용했습니다. 배속은 요청 값으로 실제 처리 속도를 뜻하지 않습니다.

v12는 scripted9_before_learned_latest에서 고정한 v12-before-learned입니다. 추가 학습 후 모델의 성적으로 읽으면 안 됩니다. v11은 참가하지 않았습니다.

결과의 범위

자연 종료된 유효 경기만 포함했습니다. 로컬 Python 정책 리그이며 공식 제출 서버의 성적은 아닙니다. 버전별 관측·상태 처리와 planner 구성이 달라, 순위만으로 특정 신경망 구조나 학습 방법의 인과효과를 분리할 수 없습니다. 행동 원인을 확정하려면 별도 trace 분석이 필요합니다.
