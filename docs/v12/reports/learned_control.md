# v12: 고정 작업 점수와 강제 행동을 제거한 추가 학습

2026-10-27. 사용자의 중단·수정 요청과 “행동을 하드코딩하지 말 것” 조건을 반영했다. 기존 실험은 **3,057,458스텝, 87 wave**에서 중단됐으며, 수정한 실험은 실행하지 않았다.

## 시작·재개

프로젝트 루트에서 다음 한 줄을 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\code\v12\finetune_learned.ps1
```

Bash에서는 `bash code/v12/finetune_learned.sh`를 사용한다. 이후 중단하고 같은 명령을 실행하면 **새 실행 자신의** 마지막 확정 체크포인트에서 재개한다. `--status`, `--stop`, `--dry-run`도 동일하게 지원한다. `--dry-run`은 준비 상태만 확인한다.

새 이름은 `scripted9_learned_v12`다. 시작 시 72경기의 기준 평가를 창 없이 수행하고, 학습 수집 단계에서는 **표시 창 1개 + 백그라운드 15개**를 사용한다. 모두 time_scale 50이며, 평가 전에는 학습 pool을 닫고 평가 후 다시 연다. 따라서 평가 중에는 창이 보이지 않는다. 이전의 `finetune_scripted.ps1` 명령 대신 위의 새 명령을 사용한다.

## 정책 변경

새 모드는 `policy_mode: learned`이며, 기존 모드를 기본값으로 유지해 과거 정책·제출물과 구분한다.

| 항목 | 기존 모드 | 새 모드 |
|---|---|---|
| 작업 점수 | 수동 prior + 신경망 보정 | **신경망 점수만 사용** |
| 작업 후보 | 수동 우선순위로 최대 24개 선별 | 물리적으로 가능한 후보 전체 |
| 작업 유지 | 일정 시간 및 변신 작업 강제 유지 | 매 의사결정 시 신경망이 유지·변경 선택 |
| 근접 회피 | 가까운 적을 감지하면 작업보다 회피 우선 | 회피도 명시적인 작업 후보로 두고 신경망이 선택 |
| 정체·배달 지연 | 시간 기준 차단·목표 초기화 | 관측으로 제공하며 행동 강제 없음 |
| 헌터 수 | 전략적 상한 2명 | 수동 상한 제거; 특정 인원이나 비율을 강제하지 않음 |
| 정체 관측 | 거의 제자리인 이동만 감지, 작업 나이 100스텝 이후 포화 | 목표까지의 관측상 최단 도달 거리 갱신 여부, 무진전 시간·작업 나이를 로그 척도로 표현 |

무진전 관측은 목표 중심까지의 유클리드 거리에서 계산한다. 우회가 필요한 상황에서도 값이 증가할 수 있으므로 이를 곧바로 실패로 판단하거나 다른 행동을 강제하지 않는다. 학습 입력일 뿐이다.

캐리어 최대 1명, 유닛의 실제 클래스 능력, 적 기지·벽, 작업 용량 등의 게임 규칙과 물리적 제약은 유지한다. **기존 경로 탐색과 회피 방향 계산은 선택된 작업을 실행하는 기하학적 이동 기능으로 남는다.** 이번 변경은 작업·회피 선택을 학습하는 방식이며, 연속 이동 방향까지 신경망이 직접 생성하는 end-to-end 정책은 아니다. 상대 ID에 따라 행동을 정하거나, 헌터 전환을 강제하거나, 일정 시간이 지나면 목표를 강제 변경하는 새 규칙은 넣지 않았다.

신경망은 기존 **64입력, 6,273파라미터** 구조를 유지한다. 다만 입력 일부의 의미를 변경했으므로 feature schema를 `blackout.v12.features.learned.1`로 분리한다. 같은 가중치를 읽을 수 있다는 것이 같은 행동·승률을 의미하지는 않는다. 고정 prior 제거로 초기 성능이 낮아질 수도 있어 새 기준 평가가 필요하다.

## PPO와 학습 신호

후보를 신경망 점수로 먼저 잘라내면 업데이트 도중 정책의 선택 가능 집합이 달라질 수 있다. 새 모드는 모든 적법 후보를 사용하고, 기록된 후보·확률을 그대로 재생한다. 후보 수가 다른 이벤트는 불가능한 선택으로 패딩해 정확한 공동 배정 확률을 유지한다.

- 경험 전체는 CPU 메모리에 유지하고 필요한 minibatch만 GPU로 옮긴다. 기본 128이지만 후보 수가 24보다 많으면 배치 크기를 줄여 GPU 메모리 사용을 제한한다.
- 기존 PPO에서 사용되지 않던 entropy 계수를 실제 목적함수에 연결했다. 공동 배정의 정확한 entropy를 minibatch당 무작위 최대 16개 이벤트에서 계산하고, 유닛 수로 나누어 **0.01**을 적용한다. 특정 행동에 가산점을 주는 방식이 아니다.
- actor 학습률은 1e-4에서 **3e-4**, critic은 3e-4를 사용한다. clip 0.2, target KL 0.02, 최대 4 epochs는 유지한다.
- GAE lambda는 .9975에서 **.9995**로 바꾼다. 코드가 primitive-step 길이만큼 lambda를 거듭제곱하므로, 긴 작업의 결과를 앞선 선택에 전달하는 범위를 늘리려는 설정이다. 개선 효과는 아직 실험하지 않았다.
- 승패 목적과 기존 potential shaping은 유지한다. 헌터 사용·특정 상대 공략 등의 추가 보상은 넣지 않았다.

`updates.jsonl`과 `progress.json`에 실제 entropy, 적용 minibatch, 후보 수, 가중치 변화량, 점수 크기, 선택한 작업 종류별 횟수, 최대 무진전 입력을 기록한다. 작업 횟수는 의사결정 기록 수이며 독립적인 작업 완료 횟수가 아니다.

## 가중치·예산·평가 보존

중단 시점 `latest.pt`의 scorer와 critic을 복사해 새 실행의 초기 가중치로 사용한다. optimizer는 새로 시작하고, 기존 rollout은 새 PPO 업데이트에 재사용하지 않는다. 수정된 정책으로 새 경험을 수집한다.

- 이전 학습량: **3,057,458스텝**.
- 새 추가 예산: **5,331,150스텝**. 기존 목표 8,388,608에서 남은 분량이다.
- 자연 종료하는 16경기 wave 단위로 예산을 검사하므로 마지막 wave만큼 초과할 수 있다.
- 새 스텝은 `env_steps`, 부모 학습량은 `parent_env_steps`, 둘의 합은 `lineage_env_steps`로 구분한다. 서로 다른 정책 모드의 학습을 하나의 동일 실험 결과처럼 해석하지 않는다.
- 개발 평가 72경기, 약 524,288스텝마다 평가, 최약 상대 승률을 우선한 모델 선택, 독립 확인 평가 576경기라는 절차는 유지한다. 9종 모두 전승이라는 목표도 유지하지만 달성을 보장하지 않는다.
- 새 train/dev/confirmation 시드 영역은 각각 610만/710만/720만부터 시작한다. 기존 두 실험에서 기록한 실제 맵 해시는 동결한 부모 registry를 통해 모두 제외한다.

과거 최고 개발 성능은 **67승/72경기(2,132,431스텝)**였고, `best.pt`도 별도로 보존했다. 새 실행은 최신 학습 경험을 반영한 `latest.pt`에서 시작한다. 바뀐 정책 모드에서는 어느 부모 체크포인트가 더 좋은 출발점인지 평가하지 않았다.

Python 두 파일 제출은 가변 후보 수를 지원한다. 기존 고정 폭 ONNX 경로는 새 모드를 명시적으로 거부한다.

Unity 없는 점검으로 기존 가중치 호환, 수동 prior 무시, 학습 선택에 따른 hold/evade, 변신 취소 가능성, 24개 초과 후보, 강제 행동 없는 정체 관측, 가변 폭 패딩과 확률 보존, entropy gradient, 재개·중단 경계를 확인했다. 동결 초기 가중치를 이용한 합성 관측 1건의 CPU/CUDA log-prob 차이는 0이었다. 이 확인에서는 optimizer 업데이트도 수행하지 않았다. 별도의 PPO 단위 검사는 작은 가상 데이터와 임시 모델만 사용했다.

실제 Unity 처리량·새 승률은 측정하지 않았다. 16개 병렬은 이전 Q2 수집 측정의 최선값을 재사용한 것이며, 후보 수와 학습 연산이 늘어난 새 모드의 최적값이라고 주장하지 않는다. **새 실험은 사용자가 위 명령으로 시작해야 한다.**
