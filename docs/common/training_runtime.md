# 학습 실행 코드의 공통 설계 원칙

2026-11-02 사용자 요청에 따른 기준이다. 앞으로 새로 작성하거나 개편하는 학습용 병렬 경기 수집 코드에 적용한다.

## 경기 종료 시 다음 경기 배정

**경기 하나가 끝나면 그 슬롯에 다음 경기를 바로 배정한다.** 다른 슬롯의 경기들이 모두 끝날 때까지 기다린 뒤 다음 묶음을 시작하는 구조를 기본으로 사용하지 않는다.

- 각 슬롯의 완료를 독립적으로 처리하고, 대기 중인 경기와 가용 자원이 있으면 해당 슬롯의 다음 경기를 시작한다.
- 예를 들어 16개 경기 중 3번 슬롯이 먼저 끝나면, 나머지 15개 경기의 종료를 기다리지 않고 3번 슬롯에 다음 경기를 넣는다.
- 관전용 저배속 경기나 오래 걸리는 상대가 다른 슬롯의 경기 배정을 막지 않도록 한다.
- 중단 요청, 수집 예산 소진, 자원 부족, 학습 알고리즘상 필요한 동기화 때문에 새 경기 배정을 멈추는 경우는 구분해 기록한다.

경기 배정과 학습 갱신의 동기화는 별도로 설계한다. PPO 등에서 필요한 수집 구간·정책 버전 관리를 유지하고, 배정 속도를 높이려는 이유로 서로 다른 정책 버전의 경험을 무분별하게 섞지 않는다. 학습 갱신 경계에서 대기가 필요하다면 그 이유와 범위를 해당 버전의 설계 문서에 명시한다.

이 기준은 경기 스케줄링에 관한 것이다. Unity 프로세스 재사용이나 보고서 생성 분리를 필수로 요구하지 않으며, 이번 문서화로 기존 학습·리그 실행 코드를 변경하지 않는다.
